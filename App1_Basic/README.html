Bakery App 1: Simple order desk

Start

  1. Open this app's folder and double-click Start App.cmd.
  2. Keep its command window open. The app opens in your browser at http://127.0.0.1:8000.
  3. If Windows does not recognize Python, install Python 3 from python.org with the option to add Python to PATH, then try again.

You can run both apps together. App 1 uses port 8000; App 2 uses port 8001. If a port is busy, open a terminal in the app folder and run python app.py --port 8015 --open.

Use the app

  1. The exercise starts Monday, November 23, 2026. The date is a simulation, independent of your computer clock.
  2. Click Fetch today's DMs. Only that day's supplied messages appear. Fetching twice does not duplicate them.
  3. Review eligible requests and click Accept or Reject. Each pending order shows its product, pickup, hours and sales. Blocked orders show the reason.
  4. Book a helper for a future day if needed: $100 adds four hours, once per day, with two days notice. A capacity-blocked request can then become eligible.
  5. Click Accept all & go to next day to fetch any remaining DMs, accept eligible requests in arrival order, complete today's 5 PM pickups and advance the date. You will see a confirmation before this step.
  6. Check the order table, original messages and activity history. Sunday messages include pickups on November 30 and December 1; advance further to complete those pickups. No new supplied DMs exist after Sunday November 29.

Rules

Cupcakes: $40 per dozen, 30 minutes per dozen. Cakes: $120 each, two hours each. Orders use only their pickup day's hours. Each day has eight hours, or twelve with one helper. Orders, changes, cancellations and helpers require at least two calendar days notice.

New orders need the baker's acceptance. Changes and cancellations are applied when fetched if valid; blocked changes leave the original order intact. Existing CSV orders start accepted. Pending requests do not reserve capacity; acceptance always rechecks availability. Every acceptance must still satisfy today's notice deadline.

Team preparation schedules

Choose the Baker schedule or Helper schedule tab and a pickup date. Accepted and completed orders are divided into whole cakes or dozens of cupcakes. Assumed shifts are baker 9 AM-5 PM and helper 5-9 AM, so one oven is never booked twice. Helpers receive work when accepted demand exceeds eight hours; a helper booked on a lighter day remains available. These are suggested baking schedules; additional decorating, cooling and packing times are not provided.

Gantt chart

Select Gantt chart and a pickup date to see both people on the same 5 AM-5 PM timeline. Each accepted order has a labeled row. Green bars show the baker; purple bars show the helper. Hover over a bar for its full timing and order details. On narrow screens, scroll horizontally to see the complete day.

Undo and keyboard navigation

Undo reverses the latest successful change, including a fetch, acceptance, rejection, helper booking or day close. It restores the prior messages, orders, costs and simulation date. Only one undo step is available, with no redo. A repeated fetch or failed action preserves your undo point. Use Left/Right, Home or End to switch between focused schedule tabs.

Money

Committed sales = accepted and picked-up orders, across all loaded pickup dates. Picked-up sales = completed pickups. Helper bookings = $100 per booked helper. Sales less helpers = committed sales minus helpers; this is not full accounting profit because ingredient and other costs are not provided.

Save, stop and reset

Every action saves automatically to bakery.db in this app's folder. Close the command window or press Ctrl+C to stop. Restarting preserves your place. To start over, stop the app and rename bakery.db to bakery-backup.db. Restarting creates a fresh exercise; the renamed file remains your backup.

Implementation

One app.py serves plain HTML, CSS and JavaScript with Python's standard library and SQLite. No packages, Node.js, AI calls, online accounts or live Instagram access are needed. The daily HTML files are local fixtures, not fetched from Instagram. The server binds only to this computer. Both apps implement the same rules; App 2 adds the calendar layout from the structured-design lecture.

Data tables: Orders, Days, Messages, Audit and Meta. Hours, prices and totals are calculated from product quantities and helper flags. The server validates every action in a database transaction. The message source/day/index key prevents duplicate imports. Valid changes match customer name and pickup date, as these are the identifiers supplied in the example messages.

Tests: in the parent Lecture9 folder, run python test_apps.py. These use isolated temporary databases, never your saved exercise. See the parent Design_and_Test_Plan.html for wireframe, data diagram, lifecycle and assumptions; see Test_Results.txt for results.
