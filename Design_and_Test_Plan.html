Two bakery apps

App 1 implements the problem on PDF pages 13-17 as a simple order desk. App 2 implements pages 18-25 with a calendar board, explicit lifecycle, activity history and the design below. Both are local Python web apps with separate SQLite databases. The business rules are deliberately consistent across versions.

Implementation plan

  1. Extract the starting orders and the seven daily message files. Ignore the unrelated Workflow Builder.
  2. Model days, orders, imported messages and history in SQLite.
  3. Implement fixed-rule fetching, acceptance, rejection, changes, cancellations, helper bookings and day closing.
  4. Build the basic order desk, then the structured calendar layout.
  5. Run isolated regression tests for the full week, with and without helper bookings. Check desktop and narrow layouts.

Hours, prices, day totals and order counts are derived, avoiding conflicting copies. A helper flag derives both capacity (12 hours) and cost ($100). Imported message keys prevent duplicates. Messages identify existing orders by customer and pickup date because the supplied changes contain no order IDs.

Lifecycle

Fetch new order -> Requested (eligible) / Incompatible (rule failed)
Requested -> Accepted (baker accepts; rules rechecked)
Requested / Incompatible -> Rejected (baker rejects)
Incompatible -> Requested (capacity becomes available before deadline)
Requested -> Incompatible (capacity fills or deadline passes)
Accepted -> Picked up (close pickup day at 5 PM)
Accepted / Requested / Incompatible -> Cancelled (valid cancellation)
Valid change -> update same active order; preserve its status
Invalid change or cancellation -> preserve order; log blocked message

Actions and assumptions

ActionChecks and effect
FetchRead only today's provided HTML. New orders get an explicit eligibility state. Valid changes/cancellations apply automatically as the lecture specifies; all outcomes are logged. No live Instagram connection.
AcceptCheck original notice and today's booking deadline; check accepted oven hours. Requested orders reserve no hours. Recheck competing requests after every acceptance.
HelperAt least two calendar days notice; at most one per day; 8 hours becomes 12, costs $100. Booking is final in this exercise.
Accept all & next dayFetch unseen messages, accept eligible requests by arrival ID, mark accepted pickups complete at 5 PM, advance one calendar day. Blocked requests remain visible. Future DMs arrive only when fetched on their day.
MoneyCommitted sales include accepted and picked-up orders across all loaded dates. Realized sales mean picked-up orders. Cancelled/rejected requests generate no sales. Net subtracts booked helpers only, not unspecified ingredient costs.
